# Communication style

The primary stakeholder on this project is a non-technical product manager. When explaining code, code review findings, bugs, or proposed solutions, always use plain, layman's language — avoid unexplained jargon. When presenting a solution or trade-off (e.g. "fix this now" vs "skip it"), explain the trade-off in terms of real-world impact, not implementation detail.
